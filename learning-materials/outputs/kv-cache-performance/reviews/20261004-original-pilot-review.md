## 波动怎么解释

Graph轮间绝对跨度约0.123–0.340微秒，相对跨度约12.8%–37.5%。这个跨度已与多个配置之间的时间差相当。因此不能据表断言D128比D64快、B256和B1一样快，也不能据日后另一次分开运行的几个百分点差异宣称优化成功。

Eager个别进程出现18–20微秒的中位数，其他轮约8–10微秒。源代码的执行方式说明区间可能包含主机提交形成的GPU空隙，但这些输出不足以把尖峰原因唯一归结为Python、WSL、温度或某一个后台程序。此次没有GPU频率、温度和利用率的同步记录。

30个区间样本嵌套在每个进程里，不能当成90次独立进程实验；单个区间又是100次调用的平均值，不能据此计算单次请求p99。

## M05-05：从时间换算逻辑读写带宽

带宽的基本口径是“读入字节+写出字节，除以耗时”；必须与实际DRAM流量区分。[NVIDIA CUDA Best Practices Guide](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html#effective-bandwidth-calculation)

本笔记先只统计K/V载荷，**不含indices读取**：

- 读取K：B×D×2字节；读取V：B×D×2字节。
- 写入K cache：B×D×2字节；写入V cache：B×D×2字节。
- 合计：8×B×D字节/调用。仅写入载荷是4×B×D，不与读写总量混用。
- 若按每个int32索引逻辑读取一次另外统计索引，则再加4×B字节；这也不是对实际内存事务数的测量。
- 对微秒时间，十进制GB/s=字节数/(微秒数×1000)。不把GB与GiB混用。

| B | D | K/V逻辑读写字节/次 | 按Graph代表值计算的有效GB/s |
| ---: | ---: | ---: | ---: |
| 1 | 64 | 512 | 0.476 |
| 1 | 128 | 1024 | 1.153 |
| 16 | 64 | 8192 | 7.632 |
| 16 | 128 | 16384 | 14.781 |
| 256 | 64 | 131072 | 136.329 |
| 256 | 128 | 262144 | 224.654 |

例：B256、D128时，读写总量=256×128×2种数据×2字节×读写各一次=262144字节，即256KiB。用1.166880微秒计算为约224.654GB/s。

这是**复用地址条件下的K/V有效读写带宽**，未测DRAM事务或缓存命中率；不能据此计算显存峰值带宽利用率。该数值是由三轮时间代表值计算的描述指标，仍继承计时波动，不是稳定硬件上限。容量C=1024表示可用槽位，不代表每次都搬1024行；只统计本次B行。
