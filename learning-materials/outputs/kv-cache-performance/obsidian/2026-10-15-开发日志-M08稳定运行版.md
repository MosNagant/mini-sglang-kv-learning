# 2026-10-15：交付稳定运行版本

用户要求：“给我弄一个稳定的效率高的版本，你给写出来。”本次由教练实现、运行和记录。个人独立理解留待复习，不因代办增加掌握分，原 73/100 与 M05 冻结结论保持。

## 节点一：先判断上一个候选为什么不能直接用

51 号自写 Gate/Up 候选虽然生成 token 相同，但未通过完整 logits 标准。本次对历史 49 号数据增加精确整数点积审查，发现一些分歧来自非常接近 FP16 舍入边界的结果；Triton 在部分点反而更接近精确值。因而不能把“开启 FMA”或“累加更准”当作保证复现原版的修复。

结论：保留既定数值标准，研究候选不晋升。具体计数和推导见[舍入边界审查](../reviews/20261015-gate-up-rounding-conclusion.md)。

## 节点二：写出可以重复使用的运行入口

新增[stable_infer.py](../stable/stable_infer.py)：保留原版数学与 KV 写入，默认整段 decode Graph，prefill 保持 Eager；固定现有模型、环境、单请求128输入/32生成。支持初始化一次、多次生成，拒绝并发，初始化失败不静默切换。源码、权重、包版本检查与 GPU 初始化次序均明确。

这项工作的成果是可靠可复现的运行入口，使用的是上游已经实现的 Graph 功能；没有包装成自研 Triton 内核提速。

## 节点三：完整数值验收

54 号两新进程比较全部 32 步：4,861,952 个 logits 最大差 0，32 个生成 token 完全一致；Graph 实际 replay31次。保存数据的 FP32 转换只发生在 CPU 比较阶段，不改变模型。独立审计重新核对来源哈希和全部数组。

## 节点四：三轮真实耗时验收

每种方式每进程两次预热、五次完整生成；共六个新计时进程、30 个原始样本。计时包含实际 GPU 完成、相同 API 检查和输出处理，排除加载/编译/捕获/预热。

| 轮次 | 原版 Eager / ms | 整段 Graph / ms | 耗时降低 |
| --- | ---: | ---: | ---: |
| 1 | 223.293 | 133.471 | 40.226% |
| 2 | 231.265 | 129.429 | 44.034% |
| 3 | 227.794 | 134.785 | 40.830% |

30 次计时的原始 token 全部一致。真实 WSL 项目直接运行发布入口也通过，区别于只在冻结快照中通过。

结论：当前负载上，推荐原版数学＋整段 Graph 的稳定入口。基线是原版 **Eager**；没有新证据说自写算子超过原版 **Graph**。这两句话必须一起记录。

## 节点五：额外采样优化完成，未晋升

55 号把原版贪心 `argmax` 与 int32 转换一起捕获进 Graph，目标是减少主机提交；没有改变模型算术。严格检查包含同一运行对象连续输入 A→B→A：96步、14,585,856个logits与原版Graph逐位一致；B确实改变输出，再回到A则完全复现。93次候选replay全部正确命中采样结果，没有使用旧凭证。

六个新计时进程共30个样本，相对原版Graph逐轮耗时变化为 **+1.324%、−3.959%、−1.605%**。没有达到每轮至少降低3%的预设工程门槛，因此保留为实验，不纳入默认版。候选命中路径同时绕过了原版两层NVTX标记，故比较的是整体采样路径，不能把耗时变化唯一归因于减少CPU提交。

最终可用版本是53，已打包为[stable-runtime-20261015.zip](../releases/stable-runtime-20261015.zip)。54和55各30个完整请求样本都保留，两种基线分开；没有把研究负结果删掉或用Eager收益替代相对Graph的结论。
