## 本课内容

自回归模型生成过程中，注意力需要用到之前 token 的 K 和 V。缓存保留每层已经计算出的 K/V，供后续复用。此项目研究的 store 内核负责把新算出的 K/V 放入指定缓存槽；注意力计算在其他步骤进行。

本课使用逻辑二维表：C 是可容纳的 token 槽位数，B 是本次写入的 token 数，D 是每个 token 的一个 K 向量或 V 向量的元素数。

- k_cache、v_cache 各为 [C,D]。
- k、v 各为 [B,D]。
- indices 为 [B]，保存每个输入行的目标槽位。
- 此处 B 的含义是 store 调用中的 token 数，不应直接当作请求数。
- shape 表示元素数量；dtype 决定一个元素的字节数。FP16 为每元素 2 字节。

上游测试 kv_cache 的逻辑形状为 [1048576,2,128]，三个维度依次为槽位、K/V 选择、向量元素。[:,0,:] 取 K，[:,1,:] 取 V。这里的基本切片共享原有存储；二维形状不保证整张表连续。实际步长在下一课结合源码学习。

讲解例子：C=8，B=2，D=4，indices=[6,2]。
输入行 0 的 K/V 写到各自 cache 的第 6 行；输入行 1 的 K/V 写到第 2 行。其他行应保持原值。所有下标从 0 开始。
FP16 下每个 K 向量占 4×2=8 字节，V 同样 8 字节；每个 token 合计 16 字节，两 token 合计 32 字节。这是逻辑有效写入量，不是缓存总容量，也不是实际 DRAM 读写流量。
