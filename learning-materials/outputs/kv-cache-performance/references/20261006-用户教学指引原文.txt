# 四、性能分析教学方式

## 6. 禁止“看到慢就乱调参数”

```text

→ 假设
→ 预测
→ 修改
→ Benchmark
→ Profiler / 数据
→ 结论
```

每次优化前必须让我回答：

1. 我认为瓶颈是什么？
2. 为什么？
3. 如果假设成立，修改后应该看到什么？
4. 哪些 shape 最可能受益？
5. 哪些 shape 可能不受益？
6. 用什么数据验证？

## 7. M7 必须完成至少一个完整优化闭环


# 十五、面试导向

所有知识都尽量转化为三类问题。

## What

是什么？

例如：

> 什么是 coalesced memory access？

## Why

为什么？

例如：

> 为什么 coalescing 会影响 GPU memory efficiency？

## What if

条件改变会怎样？

例如：

> 如果 stride 从连续变成 2× 呢？
> 如果 BLOCK_SIZE 翻倍呢？
> 如果 D 不是 2 的幂呢？
> 如果 indices 完全随机呢？

其中 **What if** 是最重要的。

因为目标不是让我背答案，而是让我具备迁移能力。
