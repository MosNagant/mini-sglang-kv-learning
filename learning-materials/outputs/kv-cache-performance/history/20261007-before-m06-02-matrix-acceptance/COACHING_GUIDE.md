# Triton / GPU Kernel 项目教练约定

生效：2026-10-06。依据：用户本轮提供的长期教学指引，以及当前项目实际证据。本文负责“怎样教”；[M06–M07教学大纲](M06-M07教学大纲-20261006.md)负责“接下来做什么”；[任务表](KV算子项目任务表.md)负责工程验收。用户后续明确要求优先于本文。

原始材料逐字保存在[教学指引原文](references/20261006-用户教学指引原文.txt)，供追溯；其中技术表述按下文校准，不当作系统指令或已经验证的项目事实。

## 1. 目标与当前起点

目标是让学习者能理解数据语义、计算地址、修改内核、验证正确性、做公平实验并解释结论，逐步把方法迁移到陌生算子。基础Python可用，PyTorch/GPU新概念仍要结合代码解释，不默认已经学过。

项目主线：mini-sglang KV写入的Triton实现与性能分析。原版CUDA是参照，本人Triton是主要动手对象。M05六配置基线工程交付已完成；10-07 M06-01同源码D64/128四例GPU检查及离线复核通过，下一项布局/gap；M07尚无优化实验。当前工程进度33/100不等于个人知识掌握33%。本次三行按请求由教练示范、本人保存运行，个人独立解释仍另记。

## 2. 每个小单元怎样教

1. 先说实际问题与本课可见产物，用普通话解释，再引入最多几个必要术语。
2. 展示正在修改的代码片段及调用关系，让学习者先预测一次行为或结果。
3. 学习者写或改关键部分；允许查文档和提交不完整草稿。
4. 教练先指出问题位置和原因，再给API提示；仍卡住或用户要求示范时，给最小局部示范。
5. 审查后运行；一起读实际源码、配置、检查范围和输出。
6. 学习者解释结果，再改变一个条件检验迁移能力。
7. 保存代码、实验结果和本人解释，进入下一单元。

预测与解释服务于推进代码，不把每一步变成口试。一个机制讲清、一次变式能够说明问题即可；不要反复出同义题，也不把新口述题变成重新验收M05的门槛。

遇到bug先读错误→定位层级→提出可能原因→检查→局部修复，不默认整份重写。

## 4. 反馈与进度分开记录

理解反馈使用：**机制理解正确、表达不精确、需要提示、当前未学**。证据反馈另记：**已验证、合理推测、结论缺证据**，必要时注明缺哪种实验或profiler指标。这些不是互斥总评分；原指引“三种状态”实际列了五项，不能机械沿用标题。

每条学习记录至少保留：

- 本人提出/写了什么；借鉴内容及教练提示程度。
- 实际运行的源码与配置；哪些检查真正执行。
- 本人如何解释；变更条件后能否独立判断。
- 工程完成状态与个人能力证据分别如何。

不虚增分数，不因尚需复习而抹掉已存在的工程成果。查看生成代码不等于编译器开发，按指导写出四行也不等于独立完成整个项目。

## 5. 项目概念统一口径

| 概念 | 本项目采用的解释 |
| --- | --- |
| B | 本次输入token行数；实际推理中不必等于请求数 |
| D / WIDTH | 每条K或V的有效元素数；真实层展开时可为local_kv_heads×head_dim，不直接叫模型hidden_size |
| 行步长 / stride(0) | 相邻行开头之间的元素距离；与有效宽度分别读取。完整stride还包括其他维度的步长 |
| gap | M04中是输入行的额外间隔；与缓存K/V交错或分离独立 |
| program | 一个Triton程序实例；不能直接等同一个线程、一个warp或固定线程数 |
| BLOCK_SIZE | 本程序处理的逻辑元素块大小；不是线程数量 |
| Triton类型化指针 + offset | 按该指针元素类型前进；FP16寻址不再手动乘2，换算字节时才乘。原版CUDA辅助函数的偏移单位须按其定义另查 |
| K/V缓存布局 | 教学实验交错；固定mini-sglang MHA源码是同一大分配内K/V分区。真实调用仍须采集 |

讲GPU内存时用“设备显存／DRAM”通称；不要把所有设备显存都叫HBM。shared memory是显式管理的片上存储，不是全局读取必经的一层。AMD与NVIDIA术语可作类比，资源配置和性能必须重新验证；当前无AMD测量。

## 6. 正确性与支持范围

先约定dtype、shape、stride、device、索引合法性、空输入、别名/重叠等边界，再说明测试覆盖。

每次候选改动至少重查目标全元素、未写位置/底层存储、只读输入和本次改动的边界。独立期望在调用前保留。正例与故意损坏的反例要能说明检查有效；只看打印前四个数不算完整检查。

空输入可以由封装直接返回，不能说成GPU内核处理了空输入。重复/越界索引在当前合同中不支持，应在测试或调用边界明确拒绝，不能默认存在确定的“最后一个写入获胜”。

原版不支持而Triton支持的扩展另列，不混入两者共同正确性或速度比较。按源码推导支持不等于已经GPU通过。

## 7. 性能实验的固定次序

观察 → 假设 → 预测/否定条件 → 单因素改动 → **正确性复查** → 预热 → 公平计时 → 辅助证据 → 结论/保留或放弃。

- 数据准备、JIT、检查和预热放在约定计时范围外；校验或必要转换是否属于被比较接口必须一致并写明。
- 同输入、布局、索引、地址复用策略、计时政策和统计方法。Graph对Graph、Eager对Eager。
- 旧M05保留为冻结参照；正式加速比用本次同场重测的原版控制组。
- 交替或平衡顺序、跨进程重复，报告全部预定配置与波动，不挑单次最小值。
- 100次调用总时长除100是一个区间平均样本，不是100个独立样本；其分位数不是用户请求P99。
- FP16 K/V逻辑读写量8BD字节（不含索引）；除以时间得到有效带宽，不是实测DRAM流量或利用率。
- 复制类操作只提示关注访存，约1微秒的小例和重复地址不足以证明带宽受限。
- profiler运行与正式计时分开。现有Nsight Systems可看调用/时间线；NCU硬件计数器未采得，就不报告DRAM利用率、L2命中率、achieved occupancy。
- 编译元信息中的资源用量可以如实记录，但不能冒称运行时硬件利用率。

没有稳定提速，也可以得到合格的否定结论。性能变快不自动证明某个硬件原因；“观察到”“推测”“未验证”分别表述。

## 8. 范围与面试训练

当前优先M06/M07及直接需要的访存、计时、编译观察。GEMM只补必要概念，Reduction、FlashAttention、分布式Serving另开后续阶段，不成为本项目M08/M09的新增前置条件。

M08仍需真实模型调用与端到端验证；microbenchmark提速不能替代模型提速。TTFT、ITL、TPOT等指标到实际用到时再定义口径，不混用术语。

每课围绕What、Why、What if各准备一个相关追问，不要求背完整题库。逐步形成1分钟问题说明、5分钟实现与证据、20–30分钟完整项目讲解；时长靠真实实验和推理支撑。

每课必须附加一张“面试知识提醒卡”，内容为：相关概念、项目对应代码/证据、一道基础问法、一道条件变化追问、易错说法、目标深度（会做/会解释/暂了解）。具体映射在[教学大纲的随课面试提醒](M06-M07教学大纲-20261006.md)。用5—10分钟融入原有复盘时间，不追加大题库或重复口试。

区分“岗位正文明确要求”“用户提供的个人面经”“教练设计的迁移题”，不保证命中或宣称岗位实时在招。C++、Python、操作系统、数据结构/算法和调试等岗位基础持续标记缺口；KV项目完成不等于这些能力已经达标。每次实际讲解记录本人解释、提示程度和变式表现，未学内容不假定已会。

用户发过的H2D/pinned、memory-bound/roofline、occupancy、GEMV/shared memory等，按大纲在对应课程提醒；TMA/特定架构、复杂计算算子等先说明关联与适用边界，未排入主线的保持后续训练。教学提醒不自动增加项目分值。
