# M06–M07教学大纲：写出v1，再用证据改进v2

本文是新建的教学安排，与之前的复习笔记分开。教学方式见[教练约定](COACHING_GUIDE.md)；进度与分值沿用[任务表](KV算子项目任务表.md)，不另创一套计分。当前只布置第一课，其余课程按前一课结果逐步展开。

## 起点、目的和最终产物

**M05已经完成限定范围的原版基线工程交付，不重做。** 当前30/100；本人理解和独立修改能力另外记录。现有四行Triton搬运代码在指导下跑通过固定用例，新的参数化v1草稿尚未填完、尚未GPU验证。

现在要把“我知道把K/V搬到哪里”推进为：

- **M06：** 同一份源码按真实宽度/行距正确工作；形成有支持范围的接口，通过共同正确性，得到原版与v1同场成绩。
- **M07：** 从成绩中提出一个可被否定的解释，亲手做一次对应改动，验证正确性与性能，说明收益、退化和不确定性。

M06主要交付：v1源码、接口/支持范围、统一正确性记录、编译观察、首次公平对照、设计说明。
M07主要交付：冻结v1与候选v2、改动前假设卡、代码差异、正确性回归、同场对照/消融、完整结果与决定。

“v1”是后续优化的起点；“v2”只是新候选，不预设它更快。性能对照包括固定mini-sglang原版CUDA、本人v1，以及M07产生的v2。

## M06各课怎样展开

### 第1课：从写死数字变成读取参数

目标文件（WSL）：

`/home/weltlaw/projects/mini-sglang-kv/experiments/triton_store_v1.py`

现有接口提供：

| 参数 | 它告诉内核什么 | 调用方从哪里获取 |
| --- | --- | --- |
| WIDTH | 一行真正要搬的元素数 | k.shape[1] |
| SRC_ROW_STRIDE | 两条输入行开头间隔几个元素 | k.stride(0) |
| DST_ROW_STRIDE | 两条缓存K行开头间隔几个元素 | k_cache.stride(0) |

从熟悉的“行编号×行距+列下标”继续；本课新增内容是**让调用方把真实尺寸告诉内核**。行编号仍分输入pid与目标pos，四行load/store继续复用。偏移单位是元素，不额外乘FP16的2字节。

本课只支持B3、D64/128、容量8、连续FP16输入、交错缓存、int32唯一索引[7,0,3]。K/V输入共享源行距，K/V视图共享缓存行距；列步长都是1。参数标为tl.constexpr意味着按参数特化，同源码不保证同一份机器码。

只填写三个表达式：

~~~python
cols = tl.arange(0, ___)
src_offsets = ___ * ___ + cols
dst_offsets = ___ * ___ + cols
~~~

先提交三行与一句预测，再审查、保存、运行。成功输出必须对应保存源码与4个实际用例；不能把既有固定版本的PASS算到这次参数化。

[本课操作页](lessons/14-width-parameter.md)包含打开文件与运行命令。现有14号没有任意宽度CLI；本课先不使用192或其它布局。

### 第2课：布局改变，语义不变

用同一份代码解释三种配置：连续输入/交错缓存、连续输入/分离缓存、输入gap64/分离缓存。

本课重点是有效宽度和行距各有用途；不用“缓存永远2×WIDTH”替代实际stride。K/V分离也不自动表示两个独立分配；真正要看视图基址与行距。

你先判断哪些量需要改变，教练再扩大运行器fixture、合同和启动检查。保持当前K/V各自共享行距的合同，暂不增加K与V不同row stride、任意列步长等额外范围。禁止悄悄复制为连续张量来掩盖寻址问题与成本。

检查不仅覆盖目标，还包括源gap未被破坏、未命中缓存和索引。通过后再迁移到新组合，不重复整套环境安装。

### 第3课：mask保护哪些地址

计划选FP16 D192，逻辑块256。新概念只讲三件事：有效列、实际生成的列下标、读写mask。必须同时考虑K/V的load和store；row stride继续来自张量，不能用256替代实际行距。

选择192有项目依据：原版warp复制模板允许行字节数为128的倍数；192×2=384字节可选每lane4字节、每个K或V分3轮复制。**这是固定源码支持推导，尚未GPU验证。** D100对应200字节不满足原版该约束，不应直接排进共同性能对比。

教练先扩运行器的参数、fixture、签名检查和记录，再布置运行。尾部使用有明确分配边界的guard/sentinel存储；既查有效列，也查额外空间不变。mask关闭的GPU危险版本不作为必跑反例；可用安全构造的数据损坏验证检查器。

新增192先用于正确性，不自动扩大M05六配置基线。Triton-only扩展如需探索另列。

### 第4课：把内核变成可调用的算子

内核是搬运规则，外部封装负责读取张量信息、检查支持范围、确定grid并启动。

你参与写batch到grid的关系、空输入路径和关键检查。沿用M04的范围概念：FP16、CUDA设备一致、形状匹配、列步长1、支持的行距、唯一合法索引。重复索引、越界、源/目标重叠等不支持情况要明确。

校验GPU索引值可能产生同步或数据传输，不能悄悄加入某一个实现的计时范围。区分“准备阶段已验证的受信任内核调用”与“包含校验的公共接口”；正式对照对两边选择相同边界。

### 第5课：共同正确性与编译观察

先把M04已有48个GPU用例（D64/128，选定B、两种缓存布局、两种输入gap）和4个空输入适配器用例用于原版/v1共同验证。已有原版结果不能自动给v1计通过；192按新增清单单列。

预期答案独立保存；覆盖目标全部K/V、未命中/底层存储、输入和索引；保留检查器正反例。本人解释一处失败如何被检查发现，教练组织大矩阵执行和记录。

读本机版本实际可取得的一种编译产物或元信息，例如PTX/编译元数据；选择一个特化版本观察。只要求能说明源码→特化/编译→启动→GPU运行，知道编译成本不等于执行耗时。环境固定Triton3.5.1，不为追新教程API升级。

### 第6课：比较原版与v1

沿用M05六配置：B={1,16,256}×D={64,128}，容量1024、FP16、交错缓存、输入gap0、连续唯一int32索引、重复相同地址。

Graph作为主要测量政策，Eager单列。两实现使用同样的数据与准备、预热、每区间100次调用、每轮30个区间样本、3轮新进程；平衡/交替执行顺序。保存源码哈希、参数、原始样本和统计层级。沿用M05指标口径，但使用**本次同场原版**计算速度比。

速度比=当次原版耗时÷候选耗时。时间减少比例=1−候选耗时÷当次原版耗时；二者不要混用。小差异接近波动时，结论可以是“暂不能确认”。

完整成绩单、简短设计和支持范围齐全后冻结v1，进入M07。v1不要求胜过原版。

## M07：只研究一个能用实验回答的问题

### 第7课：先有观察，再选择改动

先读第6课全表，选两个有对照意义的重点配置。此时再选择候选因素，例如每个program处理的行/列分工，或启动参数；不预先决定“加shared memory一定更快”。

如果只改变num_warps，称为启动配置调优；若改变program工作分配，才按实际内容描述内核改造。每个候选先过正确性，保留v1，不覆盖原记录。

本人先填这张假设卡，教练不代填结论：

| 项目 | 本人待填 |
| --- | --- |
| 观察 | 哪个配置、哪种计时口径、差多少、波动多少？ |
| 假设 | 哪一个因素可能解释这个现象？ |
| 改动 | 只改变什么？保持哪些条件？ |
| 预测 | 两个配置分别预期怎样变化？哪个可能回退？ |
| 否定条件 | 什么结果会让我放弃或缩小这个解释？ |
| 新的正确性风险 | 多/少写、越界、尾行、并发或其它？ |
| 需要的证据 | 数据、编译观察、时间线；哪些计数器暂时没有？ |

### 第8课：完整复查、消融和决定

先跑完整约定正确性，再同场测原版/v1/v2全六配置。若假设需要随机indices、更大B/D等，预先固定为扩展实验，单列合同和控制组，不覆盖v0。

消融指撤回或切换一个关键因素，看效果是否跟着变化；不能同时改布局、计时政策和program分工后把全部收益归给一行代码。

报告全部配置、进程间变化和回退。结果包含三个层次：

1. **事实：** 在明确条件下测到什么，重复运行是否一致。
2. **解释：** 哪个假设得到支持，是否还有别的解释。
3. **边界：** 哪些硬件指标未测、哪些输入未覆盖，何时使用/不使用v2。

当前没有可用NCU计数器证据，不凭速度差编造DRAM、L2或occupancy结论。已有Systems trace证明原版调用与时间线，不替代硬件瓶颈测量。计时和profiling分开运行。

预留最多两轮主要假设迭代；若都无稳定收益，整理否定结果和后续方向，继续集成与交付。合格实验不以强制提速为结尾。
