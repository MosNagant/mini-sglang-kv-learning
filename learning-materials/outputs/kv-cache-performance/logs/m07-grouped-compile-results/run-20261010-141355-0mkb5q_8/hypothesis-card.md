# M07：六组输入下，分组究竟在哪些地方有收益？

日期：2026-10-10。本课承接31号完整grouped正确性回归。32号三方同场性能入口已完成CPU检查和独立审查，见[准备记录](../reviews/20261010-m07-grouped-six-timing-preparation.md)，可直接运行。实际GPU计时尚未运行；准备脚本不代表性能通过或本人已独立掌握。

## 本次要回答的问题

30号探索了B1/D64与B256/D128：grouped对v1在后者三轮均快，在前者三轮均慢；没有稳定超过原版CUDA。两个点同时改变B和D，不能由此断言“行越短一定越快”或“行越多分组一定越快”。

现在按M05/M06既定的六配置，保持grouped内核不变，比较原版、冻结v1和grouped。新增B16以及同一B的另一种宽度；两个已经探索过的点也在这次共同会话中测量，保证新表使用当次控制组。旧30号保留为探索证据，不把它的两组结果拼上新四组冒充同场六组，也不重复运行30号来挑最好的一次。

本人此前对B256预测“暂时不确定，但我认为应该更快”，没有给出完整机制理由；B16等新增点未给预测。以下是教练的待检验假设：每program四行减少program数量，同时改变每program的数据和线程分配，因此收益可能依赖B与D；B16可能提供两端之间的观察。实验可以否定收益，不预设新表一定更好，也不凭三个B值确定通用切换阈值。

## 固定六组与三方

| 输入行数B | 有效宽度D | v1 program数 | grouped program数 |
| --- | --- | --- | --- |
| 1 | 64 | 1 | 1 |
| 1 | 128 | 1 | 1 |
| 16 | 64 | 16 | 4 |
| 16 | 128 | 16 | 4 |
| 256 | 64 | 256 | 64 |
| 256 | 128 | 256 | 64 |

v1每program一行，grouped每program最多四行；两者均配置4warp。原版使用固定mini-sglang提交与内部启动方式，不给它套用Triton的program参数。第一轮1-warp版本作为已记录的负结果保留，不加入这次计时。

共同输入：C1024；FP16 K/V；连续输入、input gap0；交错缓存、cache guard0；列stride1，源行距D、目标行距2D；int32连续唯一索引0..B-1。相同随机数据、相同缓存与输入地址复用政策。D192、gap64、分离缓存已有正确性证据，但不混进这张六配置性能表；这张表的性能结论也不覆盖它们。

对照读法：固定D比较B，才能讨论输入行数变化；固定B比较D，才能讨论宽度变化。它们仍是不同工作量的测量，不能仅凭耗时关系认定硬件瓶颈或优化原因。

## 测量边界和重复方法

- 六配置各三个新进程，共18个worker。每个worker包含三方，原版控制组同场重测；不拿旧M05数字计算本轮加速比。
- 每方先检查本次真实C1024输入；首次编译、合同检查、数据分配与拷贝、预热、记录和结果校验在计时区间外。31号的C32回归不能代替这一步。
- Graph捕获后重置缓存，再重放并检查完整结果；避免已有正确缓存掩盖内核没有写入。每个worker保留初次调用、重置后重放及最终快照。
- 正式Triton计时使用已验证参数的直接内核启动，不计入公共封装中的索引值校验和启动探针。原版使用此前约定的上游Python/JIT入口。Eager因此仍受各自提交路径影响，不能当作纯内核计算时长。
- Graph为主要政策，Eager单独报告。每个区间包含100次调用，计得区间耗时后除100；每方每政策30个区间平均样本。三方与两政策的六项在顺序上平衡轮换。
- 总计18×3×2×30=3240个区间平均样本，不是324000个独立样本，也不报告用户请求级延迟的P99。跨进程重复保留全部三轮，不挑最小值。
- 复用相同地址与小工作集，不做缓存清空；它是这种执行政策下的微基准，不是冷缓存、DRAM带宽或模型端到端测试。profiler另行采集，不混入计时。

每个进程先取30个区间均值的中位数，再取三个进程中位数的中位数，作为该配置该实现的代表耗时。保存每轮中位数、所有区间样本和轮间变化；汇总的代表值之比与三轮配对比值分别列出，不混为一种统计量。

## 先约定如何判读

| 指标 | 含义 |
| --- | --- |
| v1/grouped | v1代表耗时÷grouped代表耗时，超过1说明grouped在这个汇总口径下更快 |
| original/grouped | 当次原版代表耗时÷grouped代表耗时，超过1说明grouped在这个汇总口径下更快 |
| 耗时下降比例 | 1−grouped耗时÷对照耗时；与速度比不是同一个百分比 |
| 三轮配对结果 | 看收益方向是否反复变化，避免代表值掩盖某轮退化 |

三轮同向只提供方向性支持，不能自动声称统计显著。收益小于或接近波动时，明确写“当前证据不足以确认稳定收益”；退化必须保留。Graph和Eager不交叉求比，不因某一口径更漂亮就替换主结论。完整采集与审查可以是工程交付，结果无加速也有价值。

如果仅部分配置对v1有收益，就记录适用配置；如果仍未稳定超过原版，就如实记录。更少program、更宽PTX访存以及相同寄存器数均不单独证明性能原因；运行时带宽、occupancy、L2等没有采得就保持未知。此阶段没有模型tokens/s、AMD硬件性能或跨架构结论。
