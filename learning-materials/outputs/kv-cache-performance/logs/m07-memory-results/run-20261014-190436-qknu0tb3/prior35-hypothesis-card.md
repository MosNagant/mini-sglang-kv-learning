## 这次比较什么

用户要求开始不同组别的效率测试。本轮将组别解释为三个实现版本及完整组/尾组输入：原版CUDA、旧Triton四行grouped、新Triton完整组条件版full_groups。两个Triton版本都固定每program4行、4warp，直接观察新if条件的影响。没有同时扫描1/2/4/8行分组或warp组合。

学员已按提示填写整除条件并运行34号。教练提供本轮假设卡、对照设计与运行器，不能记为学员独立设计了全部实验。尚未记录学员对本轮各配置的独立速度预测，不增加运行前口试门槛。

## 预先选定的六种输入

固定C512、FP16输入/缓存、int32唯一合法索引，复用34号数据构造、完整底层存储和输入/缓存布局。indices采用`(37*i+11)%512`；源数据固定随机种子、区分行号，V与K区分。

固定D比较B5/256时布局相同。跨D比较时布局、gap、guard也有变化，不能把跨宽度成绩差异全归因于D。这批配置与34号对应；旧32号C1024交错/gap0计时继续保存，不和本轮拼接成加速比。

两个Triton版本每个非空调用仍只提交一个KV kernel，含表中的多个program；原版CUDA沿用自己的启动配置。B是总输入行数，program数不是提交次数。B0属于封装空返回，不混入本次非空GPU效率表。

## 预测与判断规则（采集前记录）

教练工作假设：完整组条件在编译时已知，34号B256/D128确实省去行比较、寄存器18→14，因此可能降低该配置耗时，但不保证收益。其他满组配置也只能通过实际编译/计时确认，不能直接沿用18→14。

B5/D192的两版PTX主体相同，作为未改变该路径的对照；如果也有明显涨跌，先关注测量波动、执行顺序、设备状态等待查因素，不把它解释成省掉行判断的效果。B5/D64、D128沿用原尾组逻辑，但未逐个观察过其编译输出，不先称为已证实机器码完全相同。

判定先看同配置、同进程三臂比较，再看三轮方向和幅度。若完整组未改善，或改善方向跨轮不一致，记录为没有稳定收益，不挑最快一轮。三轮同向是本次重复的一致性证据，不是统计显著性检验或普适保证。尾组出现明显差异时先诊断测量，不继续改核心参数掩盖现象。

保留所有配置的收益、退化和波动。正确性失败则先保留错误，停止采集；旧证据不覆盖。候选通过本轮也不会自动晋升为全局实现，完整回归与实际模型路径另验收。

## 怎样公平计时

六配置各三轮独立新进程，共18个worker。每个worker包含三臂，每臂Graph/Eager分别采30个区间；每区间包含100次KV调用，再除以100，得到单次调用的区间平均。合计3240个区间均值，不能当作324000个独立计时样本。

Graph为主口径：预先捕获100次调用，用CUDA Event测replay区间后除100。Eager另列：使用之前审查过的Event计时体包围100次普通提交再除100；此口径可能含CPU提交间隙，不能称为纯内核耗时。两种政策不混算速度比。

每臂先用本轮真实输入独立检查一次，重置完整cache和guard后验证Graph replay能重新写出正确结果，再预热采样。准备、JIT、数据复制、合同/索引值检查、正确性比较和日志写入在测量区间外；Triton测可信参数的直接启动入口，不将公开封装的GPU索引转CPU检查混入其中。三臂共用同一组GPU地址与数据，所有arm/policy按预定轮转顺序采样。每个区间完成后检查完整缓存、只读输入及indices，保存初始、replay和最终快照。

本轮复用小工作集与地址，没有cache flush，不是冷缓存或DRAM带宽测试。计时不包含profiler；不添加未实测的occupancy或硬件带宽解释。源码、环境、原始样本与顺序、实际参数/数据均保存供复核。

## 怎么看输出

- `original_cuda`：同场原版参照；`accepted_grouped`：旧分组版；`full_groups`：本轮新候选。
- `grouped/full_groups`比值大于1，表示该次旧版耗时较多、新版较快；小于1反之。
- `original/full_groups`同理，但比较对象换成原版CUDA。
- 报告三轮配对比值和各臂代表中位数之比。这两种汇总可能不同，不能互相替代；代表值偏好不能覆盖逐轮退化。
- 耗时下降百分比为`(1 - 新耗时/旧耗时) * 100%`，不能将速度比直接称为耗时降幅。
- `COLLECTION_COMPLETE`只表示收集完毕，需审查全部轮次后下结论。
