## 已核对的合法边界

固定 mini-sglang 提交 `9a91cfafe754aa85daee49998176275667eb58f2`。源码依据为 [35号保存的 store.py](../logs/m07-full-groups-timing-results/run-20261010-215026-gs6vimx3/original_source/python/minisgl/kernel/store.py)、[store.cu](../logs/m07-full-groups-timing-results/run-20261010-215026-gs6vimx3/original_source/python/minisgl/kernel/csrc/jit/store.cu)、[warp.cuh](../logs/m07-full-groups-timing-results/run-20261010-215026-gs6vimx3/original_source/python/minisgl/kernel/csrc/include/minisgl/warp.cuh)与[已冻结合同](../modules/M06/src/kv_contract_support.py)。

- 原版 store.cu 第74/80行分别要求缓存、输入的列 stride 为1；K/V共享缓存侧行距，K/V共享输入侧行距。两侧行距可以不同。原版按字节换算 row stride，不能把 Triton 的元素偏移再乘一次2。
- 原版 store.py 第38—40行按缓存有效二维宽度计算复制字节数。D128/FP16每份K或V为256字节，warp.cuh 第25行起选择8字节 `uint2` 包；所有输入/输出行首须满足8字节自然对齐。元数据校验没有显式检查这一地址条件，不能以“入口没报错”替代验证。
- 当前 Triton 公共合同第113—117行只接受输入行距 D 或 D+64；D128缓存行距为 D 或 2D。因而本轮 gap0/64、分离/交错都在共同范围内。任意 gap、负 stride、列 stride≠1、K/V不同侧内行距均不扩入本轮。
- 对齐变式只将输入K/V起点偏移4个FP16，即8字节；行距仍128元素，保留原版8字节包要求。偏移1或2个FP16分别为2/4字节，不作为原版共同计时的合法配置。也不将任意FP16宽度当作原版支持：该 warp copy 要求每行字节数为128的倍数。
- 所有 indices 为连续 int32、唯一且位于 [0,C)。重复目标有写竞争，越界可能破坏存储，二者不能作为性能变式。B0是封装空返回，不进入本次非空计时。

## 最小六配置矩阵

固定 B256、D128、C1024、FP16、guard0、相同有效K/V数值、固定软件环境。全部三臂保持已接受源码；v1为4warp/单行program，grouped为4warp/四行program。原版默认128线程/block。不要把每program行数与warp数混写。

| ID | 唯一改变项（相对A） | 缓存布局 | input gap | 源/目标行距，元素 | indices | 实际地址集合 |
| --- | --- | --- | ---: | --- | --- | --- |
| A | 基准 | 交错 | 0 | 128 / 256 | 0..255 | 1套 |
| B | 输入行间隔 | 交错 | 64 | 192 / 256 | 同A | 1套 |
| C | K/V缓存布局 | 分离 | 0 | 128 / 128 | 同A | 1套 |
| D | 目标槽顺序 | 交错 | 0 | 128 / 256 | 0..255的固定种子置换 | 1套 |
| E | 输入行首对齐 | 交错 | 0 | 128 / 256 | 同A | 1套，只有K/V输入起点额外偏移8字节 |
| F | 逐调用地址复用 | 交错 | 0 | 128 / 256 | 每套同A | 4套互不重叠的真实输入/缓存，循环使用 |

D只改变目标槽顺序，必须验证排序后仍为0..255；不要换成遍布C的新槽集合，否则同时改变触及范围。源K/V行序保持原样，依据各自indices重建期望值；不同条件的最终缓存值可以不同，各条件内三实现必须完全一致。固定置换种子，例如20261014，并保存实际indices数组。

C的交错/分离不是只改一个字符串：缓存K/V相对位置和目标行距随布局共同变化。这是一个明确的布局变量，不能再细称只隔离了某一种硬件访存机制。

E的构造建议：独立一维输入backing，保留前后哨兵，正常视图起点64个FP16、E起点68个FP16；要求实际分配基址满足128字节对齐，然后生成相同行距的二维view。记录原始基址、data_ptr、storage_offset、stride、ptr%8/16/32/128；条件不满足则停止该配置。禁止 `.contiguous()` 或从可见二维切片重新 `.cuda()`，否则可能消除预定偏移。保持缓存地址对齐不变。预期不保证向量宽度变化：已有grouped D128的KV指令是8字节的v2.b32，E仍满足8字节对齐，必须看本轮实际编译输出。

F要求100次调用按槽0、1、2、3循环，每套25次。不能只分配更大C而始终写同一批槽，也不能只在100次区间之间换一次地址并称为逐调用轮换。所有条件统一采用4项调用选择表：A—E的四项引用同一套，F引用四套；这样Eager不会仅在F多出Python选择逻辑。计时前将选择序号置0，Graph捕获保存实际100次地址序列。Eager仍包含这种提交开销，单列说明。

F每套应有可区分的输入数据和独立期望，以发现错误复用第一套的缺陷。有效触及数据按K/V输入、被写K/V及indices计算，约257KiB/套，四套约1MiB；实际分配因C1024及哨兵更大。不得将此称为冷缓存、超过L2容量或实测DRAM测试。它只验证减少相同地址连续复用后的敏感性。

## 计时、检查与事前判断

沿用每配置3个fresh worker、同worker三臂、每政策30区间×100调用：六配置共18worker、3240区间均值；Graph为主、Eager单列，保存全部原始样本和轮转顺序。此处只固定输入变量；A与变式分别在不同进程测量，不称同进程配对。三臂速度比仍在相同条件/同worker配对；跨条件差异要保留跨进程设备波动限制，不能直接定位硬件根因。

工作假设与否定规则在采集前冻结：

1. 行距、布局、目标顺序、合法对齐及地址复用可能改变耗时，但不预设哪一版获胜。F减少立即复用可能增加耗时；若未出现一致变化，记录该足迹下未观察到影响，不反复扩大直到出现慢例。
2. 每实现分别报告三个轮次的“变式/A”耗时比；候选还报告每条件的同worker“原版/候选”比。代表中位数之比与逐轮比值分别保存。
3. 可采用保守工程筛选线：三个预定轮次均同方向且每轮幅度至少3%，才标为本轮可重复的条件敏感信号；否则记作小幅或方向不一致。3%仅为事前工程阈值，不是统计显著性标准。即使三轮同向，也不据此自动建立通用dispatch阈值。
4. 只跑这批预定配置。正确性/环境错误先保存首错和完整数据，修复后仅按问题补必要检查；无收益不是继续扫参或重跑直到获胜的理由。

正确性必须覆盖本轮实际timing数据：每臂首次调用、完整backing重置后Graph replay、采样后检查。F对每个真实slot逐一提交初始调用并检查，重置四套后再验证完整Graph确实重写四套；不要原样沿用旧脚本“一条launch/190次检查”的断言而遗漏轮换存储。完整backing包括全部缓存未命中位置、输入padding、prefix/suffix、indices；检查和H2D/CPU索引校验都在计时与capture之外。

必要CPU控制：同槽集合置换正反例；目标顺序变化后的独立期望；offset被错误归零、gap被压平、slot意外别名、错误slot调用、guard破坏、实际参数/plan不一致均能拒绝。只用CPU控制不能声称原版或Triton已在新offset/rotation输入上正确。
