## 本课要运行的范围

| 项目 | 范围 |
| --- | --- |
| 两个实现 | frozen_v1：4warp、每program一行；grouped：4warp、每program最多四行 |
| 行数B | 0、1、2、3、4、5、17 |
| 有效宽度D | 64、128、192 |
| 缓存容量C | 32 |
| 数据与索引 | FP16 K/V；int32唯一合法目标索引；覆盖首尾缓存槽 |
| 存储组合 | 交错/分离缓存，输入gap0/64；D192另有gap64、cache guard64的两种布局 |
| 基本合同 | K/V共享各自源行距与目标行距，列stride为1；更广范围不包含在本课 |

14种布局/宽度/gap/guard组合×7种B=98配置。每种分别执行两个实现，得到196项结果：168次非空KV提交、28次合法空输入返回，另有98组结果配对。每个实现独立分配输入与缓存，分别对照调用前准备的期望，避免前一个实现写好的结果掩盖后一个实现没有工作。

另测18种非法公共调用×两个实现=36次预期拒绝，例如indices数量错误、重复/越界目标、dtype/device不匹配、输入与缓存重叠、不支持的stride。应当**在KV内核启动前拒绝**，并保持传入数据不变；校验过程可能使用GPU或同步，不能把“零KV提交”说成“绝对没有任何GPU工作”。

## 看懂三类结果

| 输出类型 | 它证明什么 |
| --- | --- |
| 非空CASE_PASS，submissions=1 | 一次KV内核提交完成本次输入；program数量另看grid |
| B0空返回，submissions=0 | 合法空输入由公共封装返回，没有提交KV内核 |
| EXPECTED_REJECTION | 故意构造的不合规调用被公共封装挡住，不是测试失败 |

每个非空用例检查目标K/V所有元素、未写缓存、cache guard、完整输入及gap、indices，并记录实际grid/参数。不能只数PASS而忽略配置与覆盖范围。

## 最值得复习的一例：B5、D192

grouped需要ceil(5/4)=2个program；第二个program产生输入行号 `[4,5,6,7]`，只有行4有效。它的行mask为 `[True,False,False,False]`，先用于indices读取；生成的列下标为0..255，但只有0..191有效。

最终K/V的load与store使用“行有效且列有效”的二维mask。由此分别检查尾部不满四行、宽度不是2的幂，以及二者同时发生的情况。input gap、cache guard依照真实stride跳过，不能拿BLOCK_SIZE代替行距。

`other=0`仅提供被屏蔽load的替代值。无效行即便得到positions=0，最终store仍必须有行mask，否则可能误写缓存槽0。这是本课应当理解的机制，不据此记录为本人已经独立掌握。
