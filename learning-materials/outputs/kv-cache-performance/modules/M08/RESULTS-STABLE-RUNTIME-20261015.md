# M08 稳定运行版本与采样提交优化

2026-10-15。用户要求教练直接写出稳定、高效、能使用的版本。本轮实现、实验和文档由教练完成，不计为学习者独立掌握；M05 保持冻结，混合验收分 73/100 不变。

## 当前验收节点

53 号运行入口已经完成实际验收：54 号完整 logits 检查通过，三对新进程共 30 个计时样本中，整段 decode Graph 相对原版 Eager 的逐轮中位耗时降低 40%～44%。真实项目默认入口也已运行通过。55 号采样捕获候选数值通过，但三轮相对原版 Graph 一慢两快，未达到预设逐轮收益门槛，不晋升。推荐仍为53稳定入口。

稳定入口：[stable/stable_infer.py](../../stable/stable_infer.py)。使用方式见[运行说明](../../stable/README.md)。它复用原版 mini-sglang 的数学计算和 KV 内核，默认启用原版整段 decode CUDA Graph；prefill 保持 Eager。一次初始化后可重复调用，避免重复加载模型和捕获 Graph。

## 为什么没有直接发布上一个 GEMV 候选

51 号真实模型检查中，生成的 32 个 token 相同，但全部 logits 未通过事前确定的数值门槛。候选不能因此成为稳定版本。

新增[舍入边界审查](../../reviews/20261015-gate-up-rounding-conclusion.md)对已有证据做 CPU 精确点积复算：516,096 个 Z 元素中，原版和 Triton 有 490 处不同；604 个争议坐标的精确整数点积支持保存的 oracle 舍入结果。490 处分歧中，Triton 更接近精确点积 326 次，原版 164 次。保存的 Triton PTX 已使用 FMA。

这说明“更接近精确点积”和“复现指定 CUDA 实现”是两个目标。没有证据支持靠增加累加精度就保证消除模型差异。本轮保留原数值门槛，转而优化提交方式；未宣称已经定位每一处模型误差的唯一原因。

## 53：稳定运行入口

- 固定 Qwen3-0.6B revision、FP16、TP1、RTX 4070 Ti 与现有依赖环境。
- 当前接口限制同时一个请求、128 个输入 token ID、32 步 greedy 生成、ignore_eos。
- 源码、模型文件和依赖版本在初始化时核验；Engine 先完成 CUDA 初始化，随后才查询设备。
- 原版模型数学、FlashInfer attention 和原版 KV 写入保持；没有未经验证的自写算子替换。
- Graph 初始化失败直接报错；若要 Eager，必须启动前明确选择，不在 GPU 初始化后静默重建 Engine。
- 每次请求记录原始 token；拒绝并发调用。自定义输入的功能支持与固定实验的验收范围分别说明。

## 54：先正确性，再完整请求计时

[严格检查原始记录](../../logs/m08-stable-runtime-check-results/run-20261015-052859-ufwymynd/result.json)来自两个新进程，分别执行相同 API 下的原版 Eager 和原版整段 decode Graph。

实际比较全部 32 步、4,861,952 个 logits，最大绝对差为 0，统一为 FP32 的保存值逐位相同，32 个生成 token 完全一致。Graph 实际 replay 31 次。Eager logits 为 FP16；Graph 第一步仍为 FP16，其余来自原版 FP32 输出 buffer，转换只用于 CPU 比较，不改变模型运算。

计时计划事前固定为三对新进程、每种方式两次预热和五次完整请求，共 30 个样本。`perf_counter` 包围同一 API 的 `generate` 和 GPU 完成等待，包含调度、采样、原始 token 记录及输出处理；排除模型加载、文件哈希、首次编译、Graph 捕获和预热。比较基线明确是原版 Eager，不是原版 Graph。

实际结果如下。每格为该新进程五次完整生成的中位耗时，包含 128-token prefill 和 32 步生成，不是单个算子时间。

| 独立进程配对 | 原版 Eager / ms | 稳定入口 Graph / ms | Graph 耗时变化 | Eager / Graph |
| --- | ---: | ---: | ---: | ---: |
| 1 | 223.293499 | 133.471155 | −40.226% | 1.6730× |
| 2 | 231.264929 | 129.428888 | −44.034% | 1.7868× |
| 3 | 227.794499 | 134.785158 | −40.830% | 1.6901× |

三轮均超过事前“每轮降低至少 3%”的工程信号线。这是本设备、固定负载的重复实测，不是任意输入的性能保证或统计显著性检验。原版数学相同，收益来自启用上游已有的整段 decode Graph；不能声称自写 Triton 超过原版 CUDA，也不能用这组结果主张超过原版 Graph。

## 55：保持数学不变的进一步尝试

候选将原版 `torch.argmax` 和 int32 转换也纳入 decode Graph。设备仍执行这些运算，目标是减少逐 token 的 CPU 提交次数，不是融合成一个新 GPU 内核。

它只在刚刚发生的 Graph replay、相同 logits 存储与布局、同一 stream、greedy 条件下复用捕获的 token 输出，且凭证只能消费一次。源码是[graph_greedy.py](../../stable/graph_greedy.py)，验证入口为[55号](../../55-verify-graph-greedy.py)。研究运行器只在53副本中加入一处 Engine 构造前的安装钩子；原版和候选都使用这份副本，53发布源码不改。

[55号严格结果](../../logs/m08-graph-greedy-check-results/run-20261015-053822-8uw6n0md/result.json)与[独立审计](../../logs/m08-graph-greedy-check-results/run-20261015-053822-8uw6n0md/independent-evidence-audit.json)已确认：同一运行对象 A→B→A 的96步、14,585,856个logits跨臂逐位一致，所有生成token一致。候选实际93次replay全部命中采样缓冲、3次prefill使用原版采样，没有残留凭证。B使用逆序128个输入ID，确实改变了4,860,789个logits元素的位模式及token序列；再回到A两臂均完整复现。审计核对108个来源哈希和192个保存数组。

实际候选命中路径还改变了 Python 采样分发及 NVTX 标记路径：原版采样有两层NVTX范围，候选命中时没有进入它们。因此后续计时比较的是完整候选实现，不是只改变CPU提交次数的严格单因素消融；不能据此把差异唯一归因于减少提交。候选没有减少原数学运算量，亦无硬件计数器证据。

原版Graph与候选各做三轮新进程、每轮五次固定A请求，共30个原始时间样本，全部token核对通过。预设每轮中位耗时至少降低3%才视为有可继续推进的工程信号。

| 独立进程配对 | 原版 Graph / ms | 采样捕获候选 / ms | 候选耗时变化 |
| --- | ---: | ---: | ---: |
| 1 | 130.001557 | 131.723237 | +1.324%（更慢） |
| 2 | 135.592818 | 130.224344 | −3.959% |
| 3 | 133.888234 | 131.739459 | −1.605% |

[全部样本与结果](../../logs/m08-graph-greedy-timing-results/run-20261015-054044-oru9f4py/result.json)及[独立审计](../../logs/m08-graph-greedy-timing-results/run-20261015-054044-oru9f4py/independent-evidence-audit.json)：109个来源哈希、全部样本、路由计数和配对计算通过复核。结论：数值验收通过，性能晋升条件未通过，**不替换53默认版**。没有为追求正结果改门槛或反复重跑。不能把54中相对Eager的40%～44%收益搬到55或自写Triton名下。

本轮新增GPU工作总量为：54两严格进程＋六计时进程＋一次实际发布入口运行；55两严格进程＋六计时进程。正式计时共60个完整请求样本，两种比较分别保留；它们不是60个相互独立的环境重复，独立进程配对每个实验只有三轮。

## 交付与继续使用

[稳定版本压缩包](../../releases/stable-runtime-20261015.zip)包含已验收入口、53/54脚本、README、发布清单和JSON结果。源码[stable_infer.py](../../stable/stable_infer.py)可直接在现有WSL环境使用；模型权重和Python环境不重复打包。

55研究候选和全部原始NPZ分别保留在项目/运行目录，不混入发布包。后续若继续提高原版Graph性能，应先依据新的profiling证据提出具体可测假设；本轮不再追加扫参。

## 复习时应讲清楚的三件事

1. 数值一致、生成 token 一致、模型质量相当是不同结论。本轮固定负载的完整 logits 一致，仍不能替代广泛质量评测。
2. CUDA Graph 降低提交开销；它不会自动减少原数学运算量，也不能将相对 Eager 的收益写成自研内核超过原版 Graph。
3. 稳定版本可以保留最快且已验证的原版计算，把研究候选和可使用入口分开。优化的价值取决于实际交付行为和证据，不取决于替换了多少原版代码。
