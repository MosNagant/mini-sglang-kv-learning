# Gate/Up 七路线实验：局部加速成立，当前模型候选未晋升

2026-10-15。教练按用户授权完成实现、GPU运行、审计及记录；个人独立掌握另行复盘。默认原版保持，M05历史基线不改，混合验收73/100不因代办实验增加。

**本轮真正得到的优化：单层同权重复用的Graph路径中，融合r4版三轮耗时降低33.21%～40.53%。但预定的28层权重轮换主目标仅有小幅改善，留出数据多数退化；真实模型全部logits未通过固定数值门。因此不能声称模型、整个框架或AMD获得加速。**

## 为什么从KV转到Gate/Up

[47号归因](RESULTS-LINEAR-ATTRIBUTION-20261015.md)中，KV占该次Eager跟踪全部GPU内核累计时长0.841%，decode Gate/Up占23.534%。我们据实际主要成本选择下一个目标。这个比例不是端到端墙钟占比，不能直接套成理论模型加速。

这里输入形状固定为FP16 `[1,1024]`，权重为 `[6144,1024]`，投影输出前3072个元素是Gate、后3072个是Up，随后计算 `SiLU(Gate)*Up`。每个投影输出仍先舍入FP16，融合没有删除原计算图的这个舍入点。原版比较对象为 **F.linear＋FlashInfer SiLU×Up完整路径**；没有把融合的一次调用与原版的单独GEMV混比。

## 七个候选与实际主指标结果

下表是step1、28层不同权重轮换、完整路径、三进程配对耗时变化的中位数。负数表示耗时减少；不是统计显著性声明。每个单元格都能在[全部样本与独立审计](../../logs/m08-gate-up-experiments/run-20261015-044242-mca3s3gj/summaryaudit.json)复算。

| 候选 | 改变的因素 | Graph耗时变化 | Eager耗时变化 | 决定 |
| --- | --- | ---: | ---: | --- |
| direct r4/w4 | 每program归约4个输出，4warp | +1.675% | +2.741% | 保留负结果 |
| direct r8/w4 | 输出行块扩大到8 | +0.955% | +0.069% | 无稳定改善 |
| direct r8/w8 | 8行块、8warp | +4.789% | +2.586% | 更多warp没有带来收益 |
| Split-K4 r4/w4 | K分4段，FP32暂存，再归约 | +9.572% | +30.794% | 增加一次内核与暂存，本配置不合算 |
| fused r4/w4 | 点积与SiLU×Up合成一个内核 | −1.419% | −7.021% | 单权重复用有明显改善；不是主目标胜者 |
| fused r8/w4 | 融合、每program处理8对Gate/Up | −2.513% | −5.023% | 按事前主指标选中，再做留出和模型检查 |
| packed fused r4/w4 | 真实重排权重为`[3072,2,1024]`后融合 | −1.003% | −5.808% | 新增336MiB权重副本，未体现稳定主指标价值 |

Eager包含Python提交、原版输出分配与候选复用输出的差异，不能解释成纯GPU内核差距。Graph采用捕获后的固定地址，每次完整区间归一化到一次路径调用；它仍不是单独内核的Nsight时长。

预打包28层的准备耗时约21.61/21.79/21.66ms，额外副本336MiB；这部分成本在计时区间外单列，不能当成免费。Split-K暂存总计2,752,512字节；暂存各位置先由第一内核写完，再由第二内核读，没有原子累加或遗漏清零。

## 使用条件改变了结论

| Graph配置 | 原版三轮μs/次 | 融合r4三轮μs/次 | 解释 |
| --- | --- | --- | --- |
| 重复同一层权重 | 14.2795 / 12.6106 / 12.6395 | 9.5371 / 7.6646 / 7.5162 | 三轮降低33.21% / 39.22% / 40.53%，局部收益成立 |
| 轮换28层权重 | 31.1437 / 30.2038 / 30.4366 | 29.3301 / 29.9794 / 30.0047 | 只降低5.82% / 0.74% / 1.42%，优势显著缩小 |

单层权重12MiB，28层共336MiB。差异说明工作集与复用方式会改变测量，支持继续调查缓存及权重读取成本；没有硬件计数器时，不能直接宣布“已打满DRAM带宽”或某级缓存命中率。

选定的fused r8在主目标三轮降低2.159% / 2.513% / 3.100%，未达到事前“代表下降至少10%，每轮至少5%”的明显改善门槛。随后冻结源码与选版，在另外两个真实解码时刻测性能：

| 留出步骤 | 原版/候选三轮比值（大于1才更快） | 结果 |
| --- | --- | --- |
| step16 | 0.983474 / 0.993156 / 0.973698 | 三轮都慢 |
| step31 | 0.974298 / 1.039284 / 0.961129 | 两慢一快 |

留出共6轮中5轮变慢。`holdout.status=PASS`只表示留出正确性与数据采集成功，不表示性能胜出；完整字段附有这一解释。不得只展示选版时的2.5%改善。

## 数值：局部通过，模型拒绝

48号从原版真实模型采集28份权重及steps1/16/31的84组X/Z/Y；32个token精确一致。49号对7候选×84组进行588项检查，全通过：

1. 全部元素finite，`abs(candidate-original) <= 0.002+0.002*abs(original)`，不允许失败元素。
2. 每个层×步单独核对FP64参照，`NRMSE_candidate <= 1.10*NRMSE_original+1e-6`。融合参照在点积后先舍入FP16，再算高精度激活及乘积；最终参照保留FP64。
3. 输入和权重不变；预打包权重还原逐位相等。
4. Graph输出先填NaN再replay；同一输入地址换入另一真实数据后再次验收，排除旧结果冒充。每臂计时后再核对Eager和Graph完整数值门。

51号接入真实模型，只替换decode Gate/Up＋激活，保持原版prefill、down projection和KV。实际替换868次decode调用、覆盖28层，未静默fallback。严格比较全部32步，每步151,936个FP16 logits：

| 检查 | 实测结果 |
| --- | --- |
| 32个greedy token | 原版和候选完全一致 |
| prefill logits | 逐位一致 |
| 全部logits有限 | 通过 |
| 全部logits数值门 | **拒绝：989,536 / 4,861,952个元素超固定容差，约20.353%** |
| 最大绝对logit差异 | 0.046875 |
| 后续模型计时 | **未运行**：没有绕过数值门，也没有放宽容差 |

这不证明模型语义质量恶化，也不证明质量等价；只说明它未满足本项目事前约定的严格数值要求。greedy token相同只说明argmax一致，不能替代整向量验证。

## 进一步拆开归约和激活差异

[独立数值分解](../../logs/m08-gate-up-experiments/run-20261015-044242-mca3s3gj/numerical-decomposition-audit.json)用FP16位模式复核全部保存数组，包含正负零：

- 七种候选的Y在84组数据、258,048个元素上彼此逐位相同。
- 每种候选均有384个Y元素与原版不同，最大绝对差0.001953125；四种非融合候选的Z各有490个元素与原版不同。
- 相同行块r8/w4的“Triton点积＋原版FlashInfer激活”和融合版本，Y差异为0。

因此这批数据没有显示激活融合额外引入差异。点积归约与舍入顺序是合理调查方向；尚不能只凭局部数组，认定全模型误差传播的唯一原因。

实际安装FlashInfer0.5.3源码已[按哈希归档](../../reviews/20261015-installed-flashinfer/manifest.json)：SiLU在float上使用`val/(1+__expf(-val))`，激活乘法后转回输出类型。Triton保留相同FP16中间边界，但`tl.exp`与归约实现不同，不能只凭公式相同要求位相同。

## 对整个项目的价值与面试复习

本轮把“改warp看看快不快”扩展为完整链条：用模型trace决定目标→保存真实输入→固定精度要求→对照七种方案→测复用条件→只选一次→独立留出→接回真实模型→根据数值门拒绝晋升。

| 基础题 | 底层追问 | 本项目能给出的证据 |
| --- | --- | --- |
| GEMV和GEMM有什么区别？ | batch1为什么不能只看Tensor Core峰值？ | 真实shape与47号对应内核；不泛化所有GEMV |
| Warp、program和输出行块是什么关系？ | 更多warp为何可能慢？ | direct三种分工、实际编译资源及负结果 |
| Split-K做什么？ | 并行增加为什么抵不过开销？ | 两个内核、FP32暂存、Graph约慢9.6%，不宣称硬件因果已证实 |
| 融合减少什么？ | 融合为何仍需保留舍入？ | 省掉独立激活提交及Z读写，但保留原FP16中间边界 |
| 缓存与工作集是什么？ | 热权重测试为何不能代表模型？ | 同权重复用降低33%～41%，轮换28权重收益缩小 |
| 输出token相同是否代表数值一致？ | 误差怎样在自回归网络传播？ | 32token相同，但约20%logits不满足严格门；传播机制待进一步定位 |
| 如何避免挑最好的结果？ | 为什么需要留出与独立进程？ | 选版前定规则，留出6轮5慢也完整保存 |

可直接用于面试的诚实表述：

> 我从KV项目的真实模型trace发现主要成本在GEMV，围绕Gate/Up做了分块、warp、Split-K、融合与权重重排的对照。融合在同权重复用的Graph测试中降低约33%～41%耗时，但28层权重轮换没有稳定明显收益。候选局部数值通过，接入真实模型后token相同但完整logits不满足预定容差，所以没有替换默认实现。我保留了全部数据，并把归约误差、缓存条件和端到端验收分开讨论。

下一步若继续追求可部署优化，应优先定位首次真实层级数值分歧，并在主工作集上确认成本；不要继续扩大盲目参数搜索或修改容差来制造成功。现有输出足以逆向复习归约、融合、精度和benchmark设计。
