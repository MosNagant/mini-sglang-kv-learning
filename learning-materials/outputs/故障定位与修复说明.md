# 故障定位与修复记录

后续更新：2026-09-29 日志确认该设备被再次删除，详见同目录《WSL故障复发记录.md》。下文是 2026-09-27 的首次修复记录。

2026-09-27 已完成设备修复，Ubuntu 安装成功，WSL 2 启动、GPU 可见性和 DNS 验证均通过。

原始故障：WSL 2.7.14 已安装成功，但 Ubuntu 创建虚拟机时失败：`CreateVm/HCS/ERROR_PATH_NOT_FOUND`。

已确认的本机证据：

- Hyper-V Worker 事件 12010 显示 `Synthetic Storage` 初始化返回 `0x80070003`。
- Windows 的 `setupapi.dev.log` 第 29965 行附近记录：2026-09-13 20:12:45，DevManView 的批量磁盘设备卸载操作删除了 `ROOT\STORVSP\0000`，删除成功。
- 修复前，对应的 Microsoft Hyper-V Virtual Disk Server 设备没有注册，`storvsp` 驱动未启动。
- Windows 自带 `wstorvsp.inf` 明确声明该设备实例和 `root\storvsp` 硬件标识。驱动包仍保存在 Driver Store，INF 和驱动文件的微软签名均有效。

恢复该设备后，原先失败的 Ubuntu 安装与虚拟机启动均成功。

## 已执行的修复

已在管理员 PowerShell 中运行同目录的 `Repair-WSL-Storage.ps1`。它调用旁边的 `Restore-HyperVStorage.cs`，使用 Windows 自带的 SetupAPI/NewDev 接口恢复缺失设备，并绑定现有的、签名有效的微软驱动。

脚本会保存原始服务注册信息，检查设备是否恢复正常。设备正常后自动继续 `Install-WSL.ps1`。如果 Windows 明确要求重启，脚本会停止并提示，重启后再次运行相同修复命令即可。

修复范围是 `root\storvsp` 虚拟磁盘服务设备；不删除 Linux 发行版，不卸载物理磁盘驱动，不下载第三方驱动。

修复已完成，无需重复运行修复脚本。原始服务注册信息、设备检查结果和安装输出保存在同目录的 `logs` 中。
